# Security & Privacy

## Overview

This application implements multiple layers of protection for deployed environments:

- **Server-side secrets**: API keys never exposed to client
- **Rate limiting**: 5 requests/minute per IP on question generation
- **Input validation**: All user input and LLM output validated
- **URL validation**: Only links to microsoft.com domains allowed
- **Type safety**: TypeScript-style validation of generated questions

---

## Rate Limiting

**Endpoint**: `POST /api/generate-questions`

**Limits**:
- 25 requests per minute per IP address
- Applies to all clients, no authentication bypass
- Supports progressive batch loading (10 batches × 10 questions = 100 total questions per exam)

**Response on limit exceeded**:
```json
{
  "error": "Rate limit exceeded. Maximum 25 requests per minute.",
  "remaining": 0,
  "resetTime": 1722470400000
}
```

**Why**: Protects against accidental or malicious API abuse draining your OpenRouter balance while allowing reasonable batch loading patterns.

## OpenRouter Cost Control

**CRITICAL**: Set spending limits on your OpenRouter API key before deploying:

1. Go to https://openrouter.ai/account
2. Find "Spending Limits"
3. Set a daily/monthly cap (e.g., $10/month)
4. Enable "Hard limit" so requests fail when limit is reached

This prevents unexpected charges if rate limiting is bypassed or misconfigured.

## LLM Output Validation

All questions generated by the LLM are validated before use:

**Checks**:
- ✅ Question type is valid (`single-select`, `multi-select`, `true-false`, `scenario`)
- ✅ At least 2 options provided
- ✅ At least 1 correct answer
- ✅ All correct answer indices in valid range
- ✅ Source URL is from `microsoft.com` domain (stripped otherwise)
- ✅ Question text is non-empty

**Behavior**: If validation fails, the entire question batch is rejected and a user-friendly error is shown. Never render unvalidated content.

---

## Environment Variables

**Secrets** (set in Vercel, never hardcoded):
- `OPENROUTER_API_KEY` — Your API key (keep private)
- `OPENROUTER_MODEL` — Model selection (public, no risk)

**Detection**: The app crashes on startup if `OPENROUTER_API_KEY` is missing, preventing accidental deployment without credentials.

---

## Client-side Protections

1. **React escaping**: All text content is automatically escaped
2. **URL validation**: Unsafe URLs stripped before rendering
3. **Confirm dialogs**: Destructive actions (abandoning exam) require confirmation
4. **No local storage of secrets**: API key never touches client storage

---

## Known Limitations

1. **Correct answers visible in DevTools**: The question payload includes correct answers from the start. This is acceptable for a practice tool but undermines integrity for high-stakes use. Acceptable tradeoff for simplicity (no database needed).

2. **No authentication**: Anyone with the URL can use the app. Authentication could be added later if needed.

3. **LLM quality**: Generated questions depend on LLM quality and prompt tuning. Some questions might have errors or be ambiguous.

4. **No encryption at rest**: Session data is not persisted, so no data to encrypt. If persistence is added later, ensure end-to-end encryption.

Before deploying to production:

- [ ] Set `OPENROUTER_API_KEY` in Vercel environment variables
- [ ] Set `OPENROUTER_MODEL` in Vercel environment variables
- [ ] Configure OpenRouter spending limits (hard cap)
- [ ] Enable Vercel HTTPS (default, automatic)
- [ ] Test rate limiting works (make 6+ requests in 60 seconds)
- [ ] Verify LLM output validation catches invalid JSON
- [ ] Monitor Vercel logs for errors or abuse patterns

## Incident Response

**If your API key is compromised**:
1. Go to https://openrouter.ai/account
2. Revoke the exposed key immediately
3. Create a new key
4. Update `OPENROUTER_API_KEY` in Vercel
5. Redeploy via Vercel dashboard

This blocks further usage within minutes.

**If rate limits are exceeded**:
- This is expected behavior; the user sees an error
- Check Vercel logs to identify patterns
- Adjust rate limits if needed in `lib/rate-limit.js`
- Consider adding CAPTCHA if abuse continues
